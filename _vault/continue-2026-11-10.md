# Protarget pDOOH — devam notu (2026-11-10)

## Proje nedir
Protarget için pDOOH (dijital açık hava) operasyon platformu: admin ekran/kampanya/creative/multiplier/deal yönetir, player'lar yayını çeker ve proof-of-play gönderir, sistem PoP × multiplier ile estimated impression hesaplar, ajans/marka read-only portalda izler. Programmatic partnerler (GAM/SSP) yalnız connector katmanında.

- Kaynak dokümanlar: `docs/source/` (Technical PRD v1.0 + Development Specification v2)
- Tam yapım talimatı (iki dokümanın birleşimi, 25 bölüm): `docs/BUILD_PROMPT.md`
  (aynı dosyanın kopyası: `~/Downloads/Protarget_pDOOH_Codex_Prompt.md`)

## Şu an ne var (yalnız iskelet)
Monorepo: pnpm workspaces + Turborepo, tamamı TypeScript.

| Yer | Durum |
|---|---|
| `packages/shared` | Enum'lar, kampanya durum makinesi (`canTransition`), hata kataloğu + hata zarfı, ayar varsayılanları, kuyruk adları |
| `packages/connectors` | `DealConnector` arayüzü, Manual + Mock (sandbox) connector, GAM iskeleti (her çağrı NotConfigured), registry, `redactSecrets` |
| `packages/i18n` | `tr.json` (varsayılan) + `en.json`, `t()` |
| `apps/api` | NestJS: `/api/v1` prefix, Swagger `/api/docs`, hata zarfı filtresi, Prisma servisi, `/health`. 21 domain modülü **boş kabuk** |
| `apps/api/prisma` | Tam şema (27 tablo) + 2 migration: `init` ve `constraints` (audit append-only trigger, flight/multiplier/geo CHECK'leri, onaylı multiplier overlap exclusion) |
| `apps/web` | Next.js: `/admin` ve `/portal` layout'ları, Spec §3 navigasyonu birebir; tüm sayfalar yer tutucu |
| `apps/worker` | BullMQ: tüm kuyruklar + periyodik zamanlayıcılar kayıtlı; işleyiciler "not implemented" logluyor |
| `apps/player` | Yalnız Player API sözleşme tipleri |
| `apps/player-sim` | Yer tutucu (çalıştırınca hata verip çıkar) |
| `infra/docker-compose.yml` | Postgres 16, Redis 7, MinIO, Mailpit, ClamAV (profil) — host portları `.env.example` içinde (5544, 6390, 9100/9101, 1125/8125; API 4100, web 3100) |

## Engel
Docker'a erişim yok: `wpu` kullanıcısı `docker` grubunda değil (`permission denied ... docker.sock`). Yereldeki Postgres 14'te de `wpu` rolü yok. Çözüm seçenekleri:
1. `sudo usermod -aG docker wpu` + yeniden oturum, sonra `pnpm infra:up`.
2. Geçici özel Postgres: `/usr/lib/postgresql/14/bin/initdb` ile kullanıcı dizininde ayrı bir instance (btree_gist uzantısı kurulu) — sudo gerektirmez.

## Yapılacaklar (sırayla)
1. Veritabanı erişimini çöz (yukarıdaki 1 ya da 2).
2. `cp .env.example .env` (yapıldı; parolaları değiştir) → `pnpm db:deploy` → iki migration'ın hatasız uygulandığını gör.
3. Kısıtları elle sına: audit_logs UPDATE/DELETE reddediliyor mu; aynı ekranda çakışan iki onaylı multiplier reddediliyor mu; `endAt <= startAt` kampanya reddediliyor mu.
4. `pnpm build && pnpm test` tekrar; API'yi başlat, `GET /api/v1/health` 200 dönsün; worker Redis'e bağlansın.
5. İlk commit.
6. `package.json#prisma` uyarısı: Prisma 7 öncesi `prisma.config.ts`'e taşı (şimdilik yalnız uyarı).
7. Kök `README.md` yaz (kurulum, komutlar).
8. **Faz 0** (BUILD_PROMPT §23): auth (JWT + refresh, argon2), RBAC guard'ları, organization scoping sorgu katmanında, kullanıcı daveti, audit servisi, settings servisi, admin login ekranı. DoD: admin login olur; ajans izolasyonu test ile kanıtlanır.
9. Faz 1 → 8 sırayla: Inventory → Campaign (6 adımlı wizard) → Player (manifest, PoP, offline kuyruk, simülatör) → Impression + raporlama → Agency portal + pause/resume → Deal katmanı → Mock connector + sync + discrepancy → hardening (pacing, bildirimler, MFA, export, yük testi, dokümanlar).

## Bu oturumda verilen kararlar (dokümanlar açık bırakmıştı)
- Stack: NestJS + Next.js + PostgreSQL/Prisma 6 + Redis/BullMQ + MinIO.
- Referans player: Chromium kiosk / Electron + headless simülatör.
- İlk gerçek connector yazılmıyor: Manual + Mock + GAM iskeleti (partner seçimi açık iş kararı).
- Portalda spend ve revenue share organizasyon bazında ayar, varsayılan kapalı.
- `RESUMING` ve `LIVE_WITH_EXTERNAL_ERROR` durumları Spec'teki "Resume mirrors the above" ifadesinden türetildi.
- Multiplier overlap: aynı ekran + aynı `specificityKey` (daypart + gün seti; "" = genel) için iki onaylı profil aynı anı kapsayamaz; daha spesifik profil genelin üstüne binebilir.
- DB kolon adları camelCase (Prisma varsayılanı), tablo adları snake_case.
